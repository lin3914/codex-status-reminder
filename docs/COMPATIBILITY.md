# 兼容性与验证范围

## 处理器与系统

app metadata 和原生恢复 helper 的最低版本保持 macOS 12.0。Swift Package 中部分历史模型库声明 macOS 14，是开发／兼容库，不是当前 Electron 安装包的另一个应用。没有仅因整理仓库而提高当前安装包的最低系统版本。

候选 CI 使用 macOS 14（arm64）、macOS 26（arm64）和 macOS 26 Intel 的官方 runner。这是计划中的自动化构建矩阵，不是已经运行成功的 GitHub Actions，也不是证明 macOS 12/13、真实多显示器、全屏、睡眠唤醒与登录项均通过的实机结果。

发布前还需真实 Apple Silicon Mac；Intel 构建成功也不能替代 Intel Mac 安装与交互验收。初次只公开已验证的处理器包。

## Codex

应用自动发现可执行文件、环境指定的数据位置、上次有效位置和标准数据目录；不绑定开发者家目录或某一安装路径。手动选择只作为连续失败后的回退。

用量优先使用 Codex app-server 的非实验 `account/rateLimits/read`。它是本机程序提供的公开协议，不是无需 Codex 的远程用量 API。任务／未读的本地兼容层依赖客户端文件格式与 IPC，需随 Codex 版本更新。

第三方 provider、API Key 或缺少周期额度的账户可能没有周额度；远端／云端会话未必完整保存在本机。不会编造百分比填满卡片。用量读取失败时可使用最后有效缓存，整次任务查询失败时可能暂留旧列表，不能将两者理解成未读状态也有缓存。

**正式下载前必须修复：**任务索引读取成功、未读状态单独失败时，当前分类会把停止任务错误归入“已处理”，待查看计数可能偏低；没有历史数据时也一样。该状态未知不等于已经查看。提醒不会因这次未读读取失败被批量清除。需补齐未知／最后有效状态处理并经真实 Codex 验收后，再宣称该失败场景可靠。

## 权限与安装身份

菜单栏标准 Tray 不需要特殊的辅助功能授权。系统允许显示状态项、正常安装路径、稳定 Bundle ID 和 Developer ID 签名共同影响分发体验，但签名不保证所有系统或第三方隐藏策略下都可见。

不要改变 Bundle ID 来“修复”重复系统条目；不要修改 Control Center、TCC 或 Dock 的私有数据库。系统残留记录不能自动视为两个运行进程，应分别确认安装副本、运行进程和系统历史。

正式公证包仍需通过真实浏览器下载形成的隔离状态验收。移除隔离属性之后能启动不能算通过。
