# Token 速率：实现规格与验收

## 展示与计算

整体与会话统一按“标题 → Token 速率 → 状态标签”排列：整体速率位于“任务进展”标题与待查看／进行中计数之间，会话速率位于会话标题与状态标签之间。去掉独立速率栏与任务页脚，保留原有最新进展的完整宽度及三行摘要。任务行88px，三行视窗276px，面板高度上限440px；保留滚动、点击打开会话、状态颜色、现有深色配色和字体。标题和进展悬停可查看完整内容。

- 进行中：显示“实时 X tok/s”。取当前轮次所选范围内已上报输出Token，除以该范围的秒数；包含思考Token，输入与缓存Token不计入。Token用量由Codex分批写入，采样值不等于逐Token瞬时流速。
- 整体：只汇总本应用已同步的顶层本地进行中会话，采用同一个所选窗口；不扩大到云端或子任务。无进行中显示0，活跃但无可靠新样本显示“—”，不沿用历史速度；样本范围及说明保留在悬停提示中，不占单独一行。
- 已停止：显示最近一轮完整运行的“平均 X tok/s”＝该轮输出Token÷完整运行秒数，含思考、工具和等待，不含用户轮次之间的空闲。
- 暂停、中止与完成均立即退出实时汇总。重复用量记录不重复累计，计数回退、缺失完整开始或结束、未知耗时均显示“样本不足”，不根据文本长度估算Token。

常规设置增加`tokenSpeedWindowSeconds`，只接受30／60／300，缺失或非法值归30；现有配置不需要迁移或重置。选择通过原设置IPC保存，并立即刷新整体与会话速率；已结束平均值保持不变。

## 数据与资源

独立实现本地只读采样，Token Monitor只用于核对用户需要和已有指标含义，不引入该程序的云连接或恢复会话策略。复用现有Codex目录发现、SQLite只读连接、worker内JSONL增量读取和文件监听。新增模块同时打入ASAR和外置worker资源。

旧记录缺少本轮开始时，对近期十条及活动会话进行一次最多8MiB的尾部回看，每次worker刷新总预算8MiB，缓存结果；记录更长或格式不完整时明确显示样本不足。仅保存数值、阶段与最多4096个近5分钟样本，不复制会话全文或凭据；切换窗口直接使用缓存。回看覆盖不足或样本数溢出时，相应实时范围显示未知，不计算偏低的速率。面板显示时每秒更新过期状态，隐藏后停止计时；每秒更新不触发数据库查询、磁盘扫描、菜单栏重建或网络请求。

本轮按用户要求将1.9.16（68）替换安装到本机“应用程序”，保留旧应用与完整配置备份，验证后恢复原有桌面组件设置，统计窗口设为默认30秒，再普通重启并关闭本地调试端口。随后获准将这份最终版本公开到GitHub，ZIP保留原始字节，DMG内应用逐文件一致，详见[本版发布说明](releases/v1.9.16.md)。保留历史1.9.15资产，不修改Token Monitor。

用户确认安全补丁升级后，将Electron由43.7.9更新到同一大版本的43.8.7，同时更新下载工具的兼容补丁依赖undici至7.30.2。证书校验通告从43.8.1起修复，见[官方安全通告](https://github.com/advisories/GHSA-jr5w-w6x2-84p9)；当前补丁见[Electron 43.8.7](https://releases.electronjs.org/release/v43.8.7)。没有迁移应用框架或修改系统权限。

## 验收
