# 1.9.13：完成提醒漏发修复

## 用户看到的问题

任务完成提醒已经打开，应用也一直在运行，但后台任务完成后没有卡片。此次复现的问题发生在应用的提醒判断链路，不是用户没有打开系统横幅。

旧版依赖 `lsappinfo` 的文字输出，正则只接受 `"CFBundleIdentifier"="..."`，而实际系统返回 `bundleID="..."`。前台状态因而被判为未知；超过 15 秒后，旧版又将尚未判明的完成记录标记为已消费，之后不会补发。

## 实际改动

- 使用打包 helper 读取 AppKit `NSWorkspace.shared.frontmostApplication`，不再解析命令行说明文字。不写系统权限、控制中心或其他应用偏好。
- 查询改为异步，并只在新完成／待判断记录需要决策时执行；已有提醒的已读清理不重复查询前台，也不增加高频轮询。
- 前台或 Codex 未读集合不可用时，保留有界的待判断记录，正常同步恢复后再判断；记录跨重启保留。
- 完成事件与未读标记可能不同步。未读集合已成功读取但标记尚未出现时，最多等待 10 分钟；不可用状态不会仅因经过 10 分钟就被当成已读。
- 已显示提醒的移除只依赖有效 Codex 已读回执或用户手动操作，读取失败不清空提醒。
- 首次启动不推送旧任务；Codex 前台不打扰；关闭提醒不补发；同一轮完成只推送一次；新一轮完成仍可再次推送。
- 保留现有外观、标题／详情、单条关闭、最新在前及分组展开交互。

持久队列版本从 2 升至 3，兼容旧游标。待判断与待查看各最多 100 条，完成游标最多 500 条。旧版已消费的历史记录不批量重放，避免修复后一口气弹出大量旧提醒。

## 验证与边界

`npm test` 覆盖完成、未读延迟、前台／未读失败、重启恢复、前台抑制、关闭、重复刷新及有界队列。`npm run test:notifications` 使用打包后的生产函数、原生前台查询和真实 Electron 卡片窗口，模拟完成事件并验证实际关闭 IPC、三条分组和有效已读回执撤下；不访问 Codex 数据，也不实际打开模拟会话。

本轮单台 Apple Silicon Mac 已完成上述固定样本和真实窗口测试。真实 Codex 任务何时完成、客户端何时写未读回执仍由 Codex 决定；模拟通过不等于所有 Codex 版本或其他 Mac 已全部通过。跨平台构建、安装隔离、系统通知回退和长期运行应按 QA_CHECKLIST 单独验收。

常驻卡片是应用自绘窗口，不是系统通知中心的横幅。只有自绘窗口不能加载而启用原生通知回退时，系统通知许可和横幅配置才影响该回退。用户主动退出应用后，卡片不会继续展示。

独立的已知问题仍保留：未读状态读取失败时，任务面板可能把停止任务误显示为已处理。此次修复确保该失败不消费新完成记录、不撤下已展示提醒，但没有重新设计任务面板的未知状态。因此正式二进制仍须先修复该状态表达并完成实机验收。
