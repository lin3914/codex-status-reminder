# 完成提醒可靠性：1.9.14 独立复核

## 用户看到的问题

任务完成提醒已经打开，应用也一直在运行，但后台任务完成后没有卡片。1.9.13 已修复一条漏发路径；1.9.14 重新按用户要求设计测试，并检查窗口、存储、队列与未读状态的失败恢复。复现的问题发生在应用链路，不是要求用户反复开启系统横幅。

旧版依赖 `lsappinfo` 的文字输出，正则只接受 `"CFBundleIdentifier"="..."`，而实际系统返回 `bundleID="..."`。前台状态因而被判为未知；超过 15 秒后，旧版又将尚未判明的完成记录标记为已消费，之后不会补发。

## 1.9.13 的漏发根因

使用打包 helper 读取 AppKit `NSWorkspace.shared.frontmostApplication`，替代命令行输出正则。前台查询异步、只在完成候选需要判断时执行。前台或未读不可用时保留候选，不再经过 15 秒就消费掉。已有提醒的已读清理不需要重复查询前台。

## 1.9.14 独立发现并修复

- 独立 ChatGPT 应用不再冒充 Codex 前台。只有实际发现的 Codex 安装身份可作为额外匹配，兼容 Codex 载体名称与路径变化。
- 首次刷新可推送启动之后的新完成，不再把它与历史任务一起吞掉；稍后才发现的启动前历史记录仍不推送。
- 提醒重新开启时记录关闭区间的截止时间，即使该期间任务索引不可读，也不会补推关闭期间的完成。
- 明确未读的候选不因旧“进行中”标签等待超过 10 分钟被消费。只有已成功读取且不包含该会话的负向回执，才在对齐期后放弃。
- 新队列缓存待查看标题与摘要。进程重启、暂缺索引或未读数据时仍可还原已保存的卡片，不拿新一轮进行中的摘要替换旧完成通知。
- 通知渲染退出、加载失败或 10 秒加载超时，只重建通知窗口；60 秒内最多 2 次自动重试，持续失败尝试系统通知，不能形成应用重启循环。手动关闭、退出或禁用时取消恢复。
- 保存状态失败不阻断本次卡片；正常同步再重试写入。没有内容变化时不重复写文件、重建通知 DOM 或复位滚动位置。
- 裁剪完成游标时保留水位，避免被裁剪的历史行每次刷新再次推送；只向窗口发送保留下来的最近 100 条提醒。
- 未读不可用明确显示“待同步”与未知数量“–”，不能冒充“已处理”或零条未读。旧格式选择最新存在字段，不把过期字段合并回当前空集合。
- 原生回退按同一轮去重；程序关闭回退通知不等同于用户手动关闭。原生投递失败保留候选并限制重试。

持久队列版本升至 4，兼容 v2／v3。待判断与待查看各最多 100 条，完成游标最多 500 条；历史记录不批量重放。旧队列没有缓存的内容需等对应索引恢复后才能还原。这是有界提醒队列，不是无限消息存档。

## 验证与边界

独立验收用例依据用户可见行为编写，不只复述实现分支；修复前先验证可失败。`npm test` 增加 8 条契约、12 条窗口／存储故障与交互用例、600 条同时完成和 2,000 次固定种子状态变化，以及生产刷新函数到面板／菜单栏的未读失败恢复。

`npm run test:notifications` 使用打包后的生产函数、原生前台查询和真实 Electron 卡片窗口，模拟完成事件，验证实际渲染崩溃后的窗口恢复、序列化恢复、单条关闭、会话主体点击 IPC、八条分组／滚动保持和有效已读撤下。所有输入为虚构任务，存储在临时目录，不访问 Codex 数据，不实际打开模拟会话。

本轮单台 Apple Silicon Mac 已完成上述固定样本和真实窗口测试。真实 Codex 任务何时完成、客户端何时写未读回执仍由 Codex 决定；模拟通过不等于所有 Codex 版本或其他 Mac 已全部通过。跨平台构建、安装隔离、系统通知回退和长期运行应按 QA_CHECKLIST 单独验收。

常驻卡片是应用自绘窗口，不是系统通知中心横幅。不写系统权限、控制中心、Dock 或其他应用偏好。只有自绘窗口持续不可用而启用原生回退时，系统通知许可和横幅配置才影响该回退；原生通知的停留方式由 macOS 控制，不能保证常驻。Electron 的通知 `show` 是投递请求，不是用户已看到的证明；签名要求、失败事件与系统行为见 [官方通知接口](https://www.electronjs.org/docs/latest/api/notification)。用户主动退出后，卡片不会继续展示。

磁盘持续不可写时仍可显示当前提醒，但进程退出前未成功保存的内容无法保证重启恢复；并未声称解决设备损坏或无限队列。系统原生回退使用替身测试覆盖程序逻辑，实际授权、已签名包与通知中心验收单独列在 QA_CHECKLIST，不能把替身测试说成系统已投递。
