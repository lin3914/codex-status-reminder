# Token 速率的10秒准实时刷新

本页记录1.9.17（69）将“打开面板后等待速率”调整为“后台保留数值样本，打开即显示”的原始机制与验收，Electron为43.8.7。后续1.9.17（73）增加延迟上报时保留参考值的规则；（74）进一步统一为纯数值展示，去掉“实时”“沿用”和“≈”，并修复长会话平均值缺失。当前口径见[Token速率规格](TOKEN_SPEED.md)。未覆盖GitHub已经发布的1.9.16（68）安装包。

1.9.17（76）将面板可见时的漏事件兜底缩短为约3秒，隐藏时仍约10秒；下文的10秒数据为（69）版本的原始验收。

## 更新方式

原有同步主要依赖文件监听，60秒低频刷新用于兜底；速率显示计时在面板隐藏后停止。打开时虽然会使用已有缓存，但文件事件漏掉或样本不完整时，缓存仍可能暂时没有有效速率。

本版保留事件监听，增加只在有进行中任务时运行的10秒单次定时检查。每次正常数据刷新都会重新安排这次检查，所以持续收到文件事件时不会再叠加定时扫描。检查在已有worker内执行，仅对已知进行中会话的文件读取大小、修改时间和文件身份；文件没变化，就结束检查。文件变动或被替换、删除后，才走原有增量同步，统一更新任务状态、未读状态、最新进展和Token样本。这样可以补齐漏事件，而不单独维护另一套任务状态判断。

打开任务面板时直接计算内存样本，不等待后台请求或重新累计统计范围。面板可见时只在新数据到达或样本到期时更新；密集到期事件合并到至多每秒一次，隐藏后不保留速率显示定时器。整个过程不新增网络请求、不启动第二个worker，不修改Codex数据或系统权限。

## 资源与异常边界

- 安静运行期间，新增检查最多每10秒一次；一个请求尚未返回时不重叠启动，失败后按相同低频重试。
- 文件未变化时，不读JSONL、认证文件或未读状态，不查询数据库，不复制样本到主进程，不更新菜单栏或渲染器。
- 结束、暂停和中止会话退出实时汇总。没有进行中会话时不再安排新增检查；其他既有低频同步继续保留，以发现后续新任务。
- 睡眠与锁屏分别记录。电脑唤醒但仍锁屏时不恢复新增检查；解锁并恢复运行后走一次正常同步。退出或切换数据连接后，旧请求的迟到结果不会更新新连接。
- 采样继续复用最多5分钟、每会话最多4096条的数值缓存；没有新增历史副本或持久化日志。
- 10秒是普通运行条件下的兜底检查周期，操作系统后台调度可能使它延后。Codex没有写入用量时仍显示“—”，不会用历史速度、文本长度或人为估算制造实时数值。
