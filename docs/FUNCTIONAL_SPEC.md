# 功能与规格：1.9.11 基线

本文按当前实现说明能力与边界。开源源码增加安全限制、开发／发布能力和文档，修正 0 小时显示、通知展开高度、菜单栏排障文案及后台完成提醒漏发；不重新设计产品，不改变任务分类、周额度计算、健康阈值或图标。

| 应用身份 | CodeX状态提醒；技术名称 Codex Companion；Bundle ID `com.lindaozhi.codexstatusreminder`；功能基线 1.9.11（62），当前源码版本 1.9.13（64） |
| 宿主 | 单一 Electron 主进程持有标准 Tray；不再打包或运行第二个菜单栏应用 |

| 菜单栏额度 | 可配置，默认开启。数字形态配小星芒，关闭数字恢复完整图标；不可读数据不伪造为 0 |

| 设置精简 | 不开放置顶／多空间／悬停策略、恢复开关、测试提醒、重定位、导出诊断、恢复推荐配置或再次引导 |

## 已知界限

兼容层并非 Codex 桌面端长期不变的公开契约。云端会话、未下发的会话、不同 Codex schema 或不提供周额度的登录方式可能无法完整展示。状态由多种只读证据组合，不能保证所有版本每一帧都与客户端同步。系统主动隐藏状态项时，应用不能越权强制显示。

已确认且尚未修复的未读边界：任务索引成功、未读状态失败时，本轮分类把空未读集合当作已读；停止任务可能归为灰色“已处理”，待查看数量偏低。这不是“未知状态”的正确呈现，也没有上一份有效未读状态缓存兜底；无历史数据时同样会发生。提醒清理接收未知标记，因此不会由该失败批量撤下。正式安装包发布前必须修复并覆盖固定样本及真实客户端验收。

提醒采用自绘面板，不能把它当作系统通知中心的一条通知。窗口渲染异常时的原生通知回退受系统设置限制。持续显示依赖应用仍运行；用户主动退出后当然不会继续展示。

点击提醒会在会话跳转完成之前撤下；跳转失败时不会自动恢复该卡片，也不会因此把会话标为已读。任务面板仍可作为再次打开的入口。

预准备提高日常打开速度，但会保留一个渲染进程；资源超限或渲染崩溃后的冷创建可能更慢。未完成所有 Mac 的延迟、内存或电池能耗测试，不承诺统一硬指标。
